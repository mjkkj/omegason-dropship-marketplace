§Playbook này là gì — đọc trước khi bắt đầu

Nếu bạn mới vào team: 3 khái niệm dưới đây là tất cả những gì cần hiểu để dùng được hệ thống. Đọc 2 phút.

📁

Folder = bộ não

Toàn bộ luật chơi, ngưỡng số, quy trình và kiến thức đã học nằm trong 1 folder. Agent đọc folder rồi mới biết phải làm gì. Không có gì "dặn miệng".

🤖

Agent = nhân viên

Claude đọc folder, làm phần nặng: research, phân tích, viết bài, dựng trang, gom số. Nó đề xuất — con người quyết.

🧩

Skill = tay nghề

Mỗi "skill" là một quy trình đóng gói cho 1 việc (vd tìm ngách, chấm sản phẩm, dựng PDP). Cả team dùng chung, ai cũng có thể tạo skill mới.

🔑 Một câu nắm ý: Bạn không "chat linh tinh" với agent. Bạn mở folder chung → giao việc theo workflow → agent dùng đúng skill + số liệu trong folder → dừng lại ở các cổng duyệt để người quyết. Kết quả và bài học được ghi lại để cả team dùng tiếp.

Vì sao dùng chung 1 folder?

Nhất quán

Mọi người chấm sản phẩm bằng cùng một bộ ngưỡng, cùng một quy trình. Không mỗi người một kiểu.

Tích luỹ

Bài học từ mỗi lần test được ghi vào knowledge/. Người sau research nhanh hơn người trước.

Chia sẻ

Ai làm ra skill/template tốt thì bỏ vào folder, cả team update playbook và dùng ngay.

§Bắt đầu trong 5 phút

Làm đúng 3 bước này là chạy được. Chi tiết skill/MCP xem mục Kho skill & MCP.

Mở folder trong Cowork. Chọn folder DRIVE full-stack-dropshipping-agent-system-all-md làm workspace. Agent sẽ đọc/ghi trực tiếp tại đây cho dự án của bạn.
Cài skill + kết nối MCP. Vào Cowork → Settings → Skills/Plugins để cài các skill ở mục Kho skill; kết nối các MCP (Shopify, WinningHunter, Notion…) trong claude.ai → Connectors. Đây là điều kiện để agent làm được việc.
Giao việc theo pid + workflow. Ví dụ: gõ "Check pipeline" để xem trạng thái, hoặc "Chạy bước tiếp cho pid-0001". Agent tự tra trạng thái và gọi đúng workflow.
⚠️ Trạng thái sống nằm ở Notion, không phải file. Drive connector chỉ tạo file mới chứ không ghi đè, nên pipeline-status.md chỉ là ảnh chụp lịch sử. Trạng thái thật của mọi sản phẩm và việc-chờ-duyệt nằm trong Notion (database Dropship Pipeline + Human Tasks). Agent luôn đọc Notion trước.

§Ai làm gì — 3 lớp vai trò

Đừng để lẫn vai. Con người chọn hướng và duyệt; agent điều phối và làm chuyên môn.

Con ngườiCEO / Lead · Human duyệt cuối
Chọn hướng & duyệt: mở niche nào, store nào scale/cut, vốn vào đâu; bấm duyệt tại các cổng (supplier, giá, deploy, launch, ngân sách).
✗ Không "ôm việc" — không tự tay research hay dựng trang.
OrchestratorAgent điều phối · SKILL.md
Điều phối: đọc trạng thái → chọn đúng workflow → gọi skill chuyên trách → gom kết quả → dừng ở cổng duyệt.
✗ Không tự publish, launch, hay tiêu tiền.
SpecialistSkill / MCP
Làm sâu 1 việc: greenlight-run, niche-hunter, pid-to-store, hook-tester, Shopify MCP, WinningHunter, Higgsfield…
✗ Không tự chuyển bước, không tự quyết.
🔑 Quy tắc vàng: Agent research · phân tích · draft · đề xuất · ghi record. Con người duyệt mọi hành động: publish, launch, ngân sách, supplier, refund, pháp lý.

Luật quyết định — trích thẳng config/thresholds.yaml

KILL
spend ≥ 5 × AOV mà chưa có sale nào
1.4
KEEP khi ROAS ≥ 1.4 (sau spend $100)
1.6
SCALE khi ROAS ≥ 1.6 · ≥ 5 purchases · +20%/48h
💰 Đừng nhìn doanh thu, nhìn contribution. Margin tối thiểu 60% → breakeven ROAS lý thuyết ≈ 1.67, mà min_roas đang để 1.4. Nghĩa là ta chủ đích chấp nhận hoà/lỗ nhẹ đơn đầu để lấy data/LTV. Luôn bắt agent tính contribution thật và nêu rõ trong Decision Record.

§Chia sẻ skill mới — vòng làm giàu playbook

Đây là phần khiến playbook "sống": ai làm ra một skill/template tốt cho dự án của mình đều có thể đưa vào folder chung để cả team dùng và update playbook.

Tạo skill. Dùng skill-creator để đóng gói quy trình bạn hay lặp lại thành 1 skill (có SKILL.md + hướng dẫn). Test cho chạy ổn trên dự án của bạn.
Bỏ vào kho chung. Lưu skill vào folder skills/ hoặc chia sẻ file .skill. Thêm 1 dòng mô tả: skill làm gì, dùng ở workflow nào, input/output.
Update playbook. Thêm skill vào đúng thẻ WF (mục "Skill/tool") và vào mục Kho skill. Bump ghi chú thay đổi để cả team biết có gì mới.
Báo team. Ping ở kênh chung (Slack/Notion) kèm 1 ví dụ dùng. Từ đó mọi người cài và áp dụng ngay.

✅ Skill tốt để chia sẻ

Quy trình lặp lại nhiều, có input/output rõ, đã chạy thật ≥ 1 lần. Ví dụ: "sinh naming campaign", "chấm supplier tự động", "brief đối thủ theo ngách".

✗ Chưa nên chia sẻ vội

Prompt xài một lần, chưa test, hoặc trùng skill đã có. Ưu tiên cải tiến skill sẵn có hơn là tạo bản trùng.

🔁 Nguyên tắc: kiến thức và tay nghề của team phải nằm trong folder — không nằm trong đầu một người. Skill mới = tài sản chung; playbook là nơi ghi lại "team hiện có những gì".

§Đóng gói plugin & cài lên Claude

Có 2 mức chia sẻ: gửi 1 skill lẻ (nhanh), hoặc gộp nhiều skill + lệnh + MCP thành 1 plugin để cả team cài một phát. Chọn mức phù hợp với thứ bạn muốn chia sẻ.

Mức 1 — Chia sẻ 1 skill lẻ (.skill)

Chuẩn bị folder skill. Một folder chứa SKILL.md (mô tả + hướng dẫn) và các file phụ trợ nếu có.
Nén thành file .skill. Zip folder đó lại và đổi đuôi thành .skill (vd niche-hunter.skill). Trong Cowork, khi trình bày file này sẽ hiện nút "Save skill".
Người nhận bấm "Save skill". Skill được cài vào Claude của họ và dùng được ngay ở lần chat sau.

Mức 2 — Đóng gói nhiều thứ thành 1 plugin

Plugin là 1 bundle gồm skills, slash-commands và cấu hình MCP. Cấu trúc thư mục chuẩn:

# cấu trúc plugin
omegason-dropship/
├── .claude-plugin/
│   └── plugin.json        # manifest bắt buộc
├── skills/                # mỗi skill 1 folder có SKILL.md
│   ├── niche-hunter/
│   ├── greenlight-run/

Phát hành qua marketplace (để cả team cài chung)

Đưa plugin lên 1 git repo và thêm file marketplace ở gốc repo:

# .claude-plugin/marketplace.json (ở repo marketplace)
{
  "name": "omegason",
  "owner": { "name": "Omegason" },
  "plugins": [
    { "name": "omegason-dropship", "source": "./omegason-dropship" }
  ]
}

Cài lên Claude

Mở trình quản lý plugin. Gõ /plugin trong phiên Claude (Cowork / Claude Code) để mở Plugin Manager.
Thêm marketplace của team. /plugin marketplace add <github-org>/<repo> Trỏ tới repo chứa marketplace.json.
Cài plugin. /plugin install omegason-dropship@omegason Sau khi cài, mọi skill/lệnh trong plugin dùng được ngay.
Cập nhật khi có bản mới. Bump version trong plugin.json, push lên repo; team chạy lại /plugin để update.
🧩 Khi nào dùng mức nào: chia sẻ nhanh 1 tay nghề → gửi file .skill. Muốn chuẩn hoá cả bộ đồ nghề cho toàn team (nhiều skill + lệnh + MCP, có versioning) → đóng gói plugin và phát hành qua marketplace.
🔐 MCP đi kèm plugin (khai trong .mcp.json) vẫn cần mỗi người authorize riêng ở claude.ai → Connectors trước khi gọi được tool.

§Khi cần chỉnh — sửa ở đâu?

Nguyên tắc: sửa đúng 1 nguồn, mọi agent tự cập nhật. Đừng dặn miệng trong chat.

✅ Nên

Sửa file nguồn → nói agent "reload thresholds" / chạy lại bước. Ghi lý do vào decision-log.

✗ Tránh

Hardcode số trong workflow, dặn miệng ngưỡng mới trong chat, hoặc cố sửa pipeline-status.md (không ghi đè được — cập nhật Notion thay thế).

§Câu lệnh mẫu để điều khiển hệ thống

Nói theo mẫu này để agent routing đúng. Luôn kèm pid + bước + dữ liệu mới (nếu có).

Check pipeline → trạng thái mọi pid từ Notion
Chạy bước tiếp cho pid-0001 → agent tra status → gọi đúng workflow
Greenlight pid-0008 lại sau khi rework offer → re-score greenlight-run
Daily brief cho các store live → Workflow 08 cho mọi pid live
Đề xuất KILL/KEEP/SCALE tuần này → Workflow 09 theo thresholds.yaml
Handoff pid-0002 sang dựng store → pid-to-store → BUILD-KIT

Checklist khởi động phiên

  • Agent đã đọc Notion Dropship Pipeline + Human Tasks?
  • Có Approval Request nào đang chờ Human? Xử lý trước.
  • thresholds.yaml còn đúng chiến lược tuần này?
  • Mỗi pid live đã có daily brief chưa?
  • Mỗi pid killed đã có learning-record chưa?
  • Kết phiên: agent cập nhật Notion + record của pid, KHÔNG sửa pipeline-status.md.
